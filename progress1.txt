1.1. APA YANG DIBUTUHKAN SEBELUM MENJALANKAN (SEKALI SAJA)
--------------------------------------------------------------------------------

Program yang harus sudah terpasang di komputer:

  1. Node.js versi 18+      — cek: node -v
  2. PostgreSQL 18          — cek: psql --version
  3. Browser modern         — Chrome / Firefox / Edge

Setup awal (hanya saat pertama kali / komputer baru):

  a. Nyalakan database:
       sudo rc-service postgresql start

  b. Buat database (kalau belum ada):
       sudo -u postgres createdb simonpedia_bapok -O postgres

  c. Install dependensi backend:
       cd server
       npm install

  d. Install dependensi frontend (di folder utama):
       cd ..
       npm install

  e. Buat struktur tabel di database:
       cd server
       npx prisma db push

  f. Isi database dengan data real Bapanas (7 pasar, 60 komoditas,
     10.844 harga, Januari 2024):
       ./node_modules/.bin/ts-node prisma/import.ts

  g. Pastikan file server/.env ada berisi:
       DATABASE_URL="postgresql://postgres:postgres@localhost:5432/simonpedia_bapok"


1.2. PROSEDUR HARIAN MENJALANKAN WEBSITE
--------------------------------------------------------------------------------

Website ini = DUA program yang harus hidup BERSAMAAN:

  1. BACKEND  → "otak" — mengolah data  → port 3001
  2. FRONTEND → "wajah" — tampilan web   → port 5173

URUTAN WAJIB (salah urutan = gagal):

  Langkah 1 — Database:
    sudo rc-service postgresql start
    (kalau muncul "already started" — aman, lanjut)

  Langkah 2 — Backend (terminal 1):
    cd server
    npm run dev
    Tanda berhasil: "Server running on http://localhost:3001"
    Biarkan terminal terbuka. Berhenti = Ctrl+C.

  Langkah 3 — Frontend (terminal 2 — BARU, jangan tutup terminal 1):
    npm run dev        (dari folder utama proyek)
    Tanda berhasil: "Local: http://localhost:5173"
    Biarkan terbuka.

  Langkah 4 — Buka browser:
    http://localhost:5173
    Muncul Dashboard SIMONPEDIA. SELESAI.

  Langkah 5 (opsional) — Verifikasi cepat backend hidup:
    curl http://localhost:3001/api/health
    Jawaban harus: {"status":"ok","message":"SIMONPEDIA API is running"}

SKENARIO KHUSUS:

  Komputer habis restart/matikan:
    Ulangi SEMUA langkah 1-3. (Ini penyebab paling sering keluhan
    "dashboard kosong" — backendnya mati setelah restart.)

  Mengakhiri sesi:
    Ctrl+C di terminal backend, Ctrl+C di terminal frontend.
    Matikan PostgreSQL (opsional): sudo rc-service postgresql stop

1.4. CARA MELIHAT DATABASE LANGSUNG DI BROWSER (PRISMA STUDIO)
--------------------------------------------------------------------------------

Prisma Studio = aplikasi bawaan proyek untuk melihat & mengedit
database lewat browser. Tidak perlu install apa pun.

  Cara buka:
    cd server
    npm run db:studio
    → browser terbuka otomatis di http://localhost:5555
      (kalau tidak otomatis, buka alamat itu manual)

  Yang terlihat — sidebar kiri berisi 5 tabel:

    Wilayah      : 1 baris (Kota Surabaya)
    Pasar        : 7 pasar pemantauan
    Komoditas    : 60 jenis bahan pokok
    Survei       : 217 kegiatan survei (31 hari × 7 pasar)
    DetailSurvei : 10.844 baris harga — TABEL UTAMA data

  Yang bisa dilakukan:
    - Klik tabel → lihat semua baris, urutkan, filter
      (mis. ketik "Cabai" di filter Komoditas)
    - Filter & sort per kolom
    - Klik tanda panah (relasi) di kolom seperti surveiId /
      komoditasId → lompat ke baris terkait di tabel lain
    - EXPORT ke CSV (tombol kanan atas tiap tabel) — berguna
      untuk laporan/makalah
    - EDIT nilai langsung: klik sel → ubah → save
      (PERINGATAN: langsung menulis ke database! Halaman web
       memakai data ini. Salah edit = data web ikut berubah)

  Catatan:
    - Prisma Studio hanya butuh PostgreSQL hidup.
      Backend (3001) TIDAK perlu jalan.
    - Setelah edit lewat Prisma Studio, refresh browser halaman
      web (F5) untuk melihat perubahan — halaman tidak auto-reload.
    - Menutup: Ctrl+C di terminal tempat perintah dijalankan.

  ============================================================================

  Pagi hari, petugas membuka aplikasi:

  6. Ambil keputusan / laporkan sesuai kewenangan

3.3. CARA KERJA EWS (EARLY WARNING SYSTEM)
--------------------------------------------------------------------------------

  EWS menjawab: "komoditas mana yang harganya bergerak ABNORMAL?"

  Langkah backend (server/src/routes/ews.ts):

    1. Untuk tiap komoditas, ambil semua harga dari semua survei.
    2. Rata-rata harga per TANGGAL (semua pasar digabung).
    3. Bandingkan 2 tanggal survei TERAKHIR:
         persenPerubahan = (rataBaru − rataLama) / rataLama × 100
    4. Tentukan LEVEL dari besar perubahan (pakai nilai mutlak):
         < 5%    → NORMAL   (hijau)
         5-10%   → SIAGA    (kuning)
         10-20%  → WASPADA  (merah)
         ≥ 20%   → KRITIS   (hitam)
    5. Level ≠ Normal → buat ALERT per pasar.
    6. Susun ringkasan: berapa komoditas di tiap level.

  Kenapa threshold 5/10/20%? Standar praktik umum pemantauan
  harga pangan — pergerakan < 5% harian itu wajar, > 20% berarti
  ada gejolak serius (biasanya dipicu gagal panen/panen raya).

  Kenapa sekarang semua NORMAL? Data Januari 2024 memang stabil:
  perubahan antar-hari terbesar hanya ~2%. BUKAN bug — bukti
  sistem jujur. Kalau diimport bulan yang volatil (mis. bulan
  sebelum Ramadan), alert otomatis muncul.

3.4. CARA KERJA PREDIKSI (RINGKAS — DETAIL DI dokumentasi.txt)
--------------------------------------------------------------------------------

  Prediksi menjawab: "kalau pola sekarang berlanjut, harga 7 hari
  lagi berapa?"

  Empat langkah:

    1. SIAPKAN DATA: satu harga per hari = rata-rata 7 pasar
       (7 harga pasar → 1 angka harian, noise hilang)
    2. TIGA METODE dihitung berdampingan:
       a. Linear Regression — pasang garis lurus di data;
          slope garis = kecepatan naik/turun (Rp/hari)
       b. Moving Average 7 hari — rata-rata jendela mingguan;
          menenangkan fluktuasi
       c. Exponential Smoothing α=0,3 — rata-rata berbobot yang
          lebih menghargai hari terbaru
    3. BLEND (yang dipakai web): campuran garis tren & harga
       terakhir — hari depan dekat lebih percaya harga hari ini,
       hari ke-7 lebih percaya tren
    4. BACKTEST — uji kejujuran: sembunyikan 7 hari terakhir,
       latih model pada 24 hari, suruh menebak 7 hari yang
       disembunyikan, hitung melesetnya (MAPE).
       Hasil nyata (Cabe Merah Besar):
         Naive (besok=hari ini)  meleset 1,81%  ← justru juara!
         Blend sistem            meleset 2,24%
         ES                      meleset 2,42%
         MA7                     meleset 3,36%
         LR                      meleset 4,90%
       Halaman web MENAMPILKAN tabel ini apa adanya + peringatan
       kalau Blend kalah dari Naive.

  Kesimpulan praktis: prediksi sistem ±2% meleset → bagus untuk
  melihat ARAH/tren, jangan dipakai untuk angka pasti.

3.5. CARA KERJA TIAP HALAMAN (POLA UMUM)
--------------------------------------------------------------------------------

  Semua halaman data mengikuti pola yang sama (React):

    1. useEffect (saat halaman dibuka)
         → fetch ke API backend
    2. Data masuk → simpan di state (useState)
    3. Kalau masih loading → tampil spinner berputar
    4. Kalau sukses → render tabel/grafik/kartu
    5. Kalau gagal → console.error (F12 → Console untuk lihat)

  Jadi kalau satu halaman bermasalah tapi yang lain normal,
  kemungkinan besar endpointnya saja yang mati — cek curl.

3.6. CARA KERJA GRAFIK & PETA
--------------------------------------------------------------------------------

  Grafik  = Recharts (library React). Data = array
            {tanggal, harga}. Interaksi hover bawaan library.
  Peta    = Leaflet + tile OpenStreetMap (peta dunia nyata,
            gratis). Tiap pasar punya lat/lng di database →
            dipasang pin merah. Popup = komponen HTML biasa.

5.3. GLOSARIUM ISTILAH
--------------------------------------------------------------------------------

  Bapok         Bahan pokok — kebutuhan sehari-hari (beras, cabai...)
  Komoditas     Barang yang dipantau (satu jenis bapok)
  Survei        Kegiatan catat harga di satu pasar, satu tanggal
  EWS           Early Warning System — alarm dini harga abnormal
  Level risiko  Normal(<5%) / Siaga(5-10%) / Waspada(10-20%) /
                Kritis(≥20%) — besar perubahan harga antar-hari
  MAPE          Rata-rata % meleset prediksi (kecil = bagus)
  RMSE          Akar rata-rata kuadrat error (dalam rupiah)
  Backtest      Uji akurasi: tebak masa lalu yang sudah diketahui
  Walk-forward  Backtest jujur: model hanya boleh lihat masa lalunya
  Naive         Baseline tebakan "besok = hari ini"
  Blend         Metode gabungan LR+harga terakhir yang dipakai web
  Frontend      Program tampilan di browser (React)
  Backend       Program server pengolah data (Express)
  API           "Juru bicara" antara frontend dan database
  Prisma        Penerjemah perintah backend → database
  Endpoint      Satu alamat API (mis. /api/ews/analyze)
  JSON          Format data teks yang dikirim antar program
  Placeholder   Halaman disiapkan tapi masih kosong
