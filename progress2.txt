BAGIAN 2 — CARA RUNNING APLIKASI (CHEAT SHEET)
================================================================================

Aplikasi = 3 komponen yang harus hidup: PostgreSQL + Backend + Frontend.

--- A. SEKALI SAJA (SETUP PERTAMA) -------------------------------------
1) Nyalakan PostgreSQL (sistem pakai OpenRC, BUKAN systemd):
     sudo rc-service postgresql start
2) Masuk DB & buat database:
     psql -U postgres -h localhost
     CREATE DATABASE simonpedia_bapok;
     \q
3) Setup backend:
     cd server
     npm install
     npx prisma db push
     ./node_modules/.bin/ts-node prisma/import.ts   # import data 12 bulan
   File server/.env harus berisi:
     DATABASE_URL="postgresql://postgres:postgres@localhost:5432/simonpedia_bapok"
4) Setup frontend:
     cd ..        (kembali ke root project)
     npm install

--- B. PROSEDUR HARIAN (TIAP MAU PAKAI) --------------------------------
Buka 2 terminal.

  TERMINAL 1 — Backend (harus hidup dulu):
     sudo rc-service postgresql start      # kalau DB belum jalan
     cd server
     npm run dev
     → tunggu tulisan "Server running on http://localhost:3001"

  TERMINAL 2 — Frontend:
     cd "<root project>"
     npm run dev
     → buka http://localhost:5173 di browser

--- C. RESET & IMPORT ULANG DATA (hati-hati: menghapus semua data) -----
     cd server
     npx prisma migrate reset --force
     ./node_modules/.bin/ts-node prisma/import.ts

--- D. LIHAT DATABASE SECARA VISUAL (Prisma Studio) --------------------
     cd server
     npm run db:studio     → buka http://localhost:5555

--- E. TROUBLESHOOTING -------------------------------------------------
- Halaman kosong / data tidak muncul:
    * Pastikan backend (terminal 1) hidup: cek http://localhost:3001/api/health
    * Pastikan PostgreSQL hidup: sudo rc-service postgresql start
- Halaman lambat / muter lama:
    * Dulu karena /api/harga kirim 34 MB. Sekarang Home & Monitoring pakai
      /api/harga/ringkasan (12 KB). Kalau lambat lagi, cek endpoint yang
      dipanggil halaman.
- Port bentrok (3001 / 5173 sudah dipakai):
    * Matikan proses lama: cari PID-nya lalu kill. Jangan asal pkill -f
      pada pola yang cocok dengan proses sendiri.
- Prediksi tanggalnya aneh (mulai 2024-02):
    * Sudah diperbaiki. Kalau muncul lagi, cek forecastRange di prediction.ts.

CATATAN PENTING soal backend sebagai proses background:
    Gunakan pola "setsid nohup ... &" agar proses tidak mati saat terminal
    ditutup. Pola "nohup ... &" biasa bisa ikut mati.

--- ANTISIPASI Q&A (siapkan jawaban) ----------------------------------

Q1: "Kenapa pakai Naive kalau lebih akurat dari metode kalian?"
A : "Betul, dan itu temuan penting. Di data yang sangat volatil, model
     sederhana bisa menang. Kami menampilkan ini secara jujur lewat
     backtest, bukan menyembunyikannya. Ini justru dasar untuk memilih
     model per komoditas, bukan satu model untuk semua."

Q2: "Kenapa tidak pakai machine learning (ARIMA, Prophet, LSTM)?"
A : "Itu roadmap. Kami mulai dari metode yang bisa dijelaskan dan
     diaudit — penting untuk data pemerintah. Backtest sudah jadi
     kerangka untuk membandingkan metode apa pun, termasuk ML nanti."

Q3: "Sumber datanya dari mana? Valid?"
A : "Bapanas / SP2KP, data resmi pemerintah. 138.054 titik harga dari
     survei harian 7 pasar selama 12 bulan."

Q4: "Kenapa datanya banyak kosong?"  → (lihat Bagian 5, jawab singkat)
A : "Tidak semua pasar melaporkan semua komoditas. Kami jujur:
     ~14% sel kosong di file sumber. Kami sudah tangani dengan agregasi
     pasar-yang-melapor, dan sedang koordinasikan definisinya ke divisi
     analisis."

Q5: "Kenapa prediksi Blend lebih buruk dari Naive?"
A : "Karena Linear Regression menganggap tren lurus, padahal harga cabai
     sangat musiman (naik jelang Ramadan, turun setelahnya). LR
     ekstrapolasi jadi meleset jauh. Blend kami masih terlalu
     membebani LR. Perbaikannya: bobot adaptif per komoditas."

Q6: "EWS-nya real-time?"
A : "EWS menghitung dari survei terakhir yang tersedia (di data ini:
     31 Des 2024). Arsitekturnya siap menerima data harian baru —
     tinggal import. Real-time penuh butuh integrasi API langsung,
     itu langkah berikutnya."

Q7: "Kenapa headernya beda-beda tiap halaman?"
A : "Kesengajaan. Tiap halaman punya konteks sendiri (breadcrumb + judul).
     Kami pakai satu komponen PageHeader agar konsisten."

Q8: "Apakah bisa dipakai petugas sekarang?"
A : "Versi ini prototipe fungsional: monitoring, EWS, prediksi sudah
     jalan dengan data real. Yang belum: login, notifikasi push, dan
     deploy ke internet."

--- RINGKASAN UNTUK DIVISI ANALISIS -----------------------------------
Data sumber Bapanas/SP2KP TIDAK lengkap: tidak semua pasar melaporkan
semua komoditas setiap hari. Ini mempengaruhi kualitas model forecasting.

--- FAKTA (dari pemeriksaan file sumber 12 bulan) ---------------------

Di file mentah (sheet harian), nilai harga kosong muncul sebagai:
  * "-"        (tanda hubung; kemungkinan: pasar tidak melapor / tidak jual)
  * 0          (nol)
  * ""         (string kosong; sisa formula)
  * "#DIV/0!"  (formula Excel error saat pembagi 0 — tidak ada data)

Dari total sel harga di sheet harian (12 bulan):
  * valid (>0)   : 161.922 sel  (73%)
  * kosong "-"   :  30.273 sel  (14%)
  * nol (0)      :      49 sel  (0,03%)
  * "#DIV/0!"    :       4 sel  (0,001%)

Contoh Januari 2024 (60 komoditas, 7 pasar):
  * 33 komoditas dilaporkan LENGKAP di 7 pasar
  * 26 komoditas hanya di 1-6 pasar (partial)
  * 1 komoditas (Beras Medium) kosong di semua pasar

Contoh nyata komoditas partial (Januari):
  - Tempe Kw III (campuran kulit)   → hanya 1/7 pasar
  - Tempe Kw II (campuran jagung)   → 2/7 pasar
  - Tempe Kw I (campuran kedelai)   → 3/7 pasar
  - Ikan Lele Segar (Uk. Sedang)    → 4/7 pasar
  - Ikan Teri Asin                  → 4/7 pasar
  - Beras Jagung                    → 5/7 pasar
  - Mentega Curah (Amanda)          → 5/7 pasar
  - dst.

--- AKAR MASALAH ------------------------------------------------------
Ini KEKOSONGAN STRUKTURAL dari sumber, bukan kesalahan sistem kami:
  * Pasar tradisional tidak semuanya menjual semua komoditas
    (mis. tidak semua pasar punya tempe industri rumahan).
  * Petugas survei mungkin tidak mengukur komoditas yang tidak ada.
  * File Excel sumber memakai formula rata-rata yang menghasilkan
    #DIV/0! saat semua pasar kosong.

--- PENANGANAN SAAT INI (yang sudah dilakukan sistem) ----------------
1. Saat import (import.ts): nilai kosong ("-", 0, "", #DIV/0!) DILEWATI,
   tidak dimasukkan ke database. Jadi DB hanya berisi harga valid.
2. Saat analisis (EWS & prediksi): dihitung RATA-RATA dari pasar yang
   MELAPOR saja. Jadi "harga rata-rata" = rata-rata pasar pelapor,
   BUKAN selalu 7 pasar.
3. Field 'jumlahPasar' disimpan → bisa tahu harga itu dari berapa pasar.

--- DAMPAK KE MODELLING FORECASTING (kenapa jadi problem) -------------
1. BIAS RATA-RATA: rata-rata dari 3 pasar berbeda komposisinya dari
   rata-rata 7 pasar. Harga komoditas jadi tidak sebanding antar hari
   bila jumlah pasar pelapor berubah.
2. TITIK DATA TIDAK SERAGAM: satu tanggal bisa didominasi 1 pasar,
   tanggal lain 7 pasar. Grafik tren jadi "bergerak" bukan karena harga
   berubah, tapi karena komposisi pasar berubah.
3. MAPE tidak apple-to-apple antar komoditas (komoditas dengan sedikit
   data punya error yang sulit dibandingkan).
4. LR & Blend rentan: lonjakan/kelangkaan data membuat regresi miring.
   Inilah sebagian sebab Naive menang di beberapa komoditas.

--- USULAN SOLUSI (opsi untuk didiskusikan) ---------------------------

OPSI A — Agregasi pasar-yang-melapor + laporkan jumlah pelapor
  (sudah sebagian dilakukan). Tambahkan: selalu tampilkan "dari N pasar"
  agar transparan.

OPSI B — Interpolasi / forward-fill celah pendek
  Isi kekosongan 1-3 hari dengan nilai terakhir. Cocok untuk celah
  sesekali, TIDAK cocok untuk kekosongan struktural (pasar yang
  memang tidak pernah jual komoditas itu).

OPSI C — Filter komoditas dengan coverage minimum
  Mis. hanya analisis komoditas yang dilaporkan >=5 dari 7 pasar.
  Mengorbankan jumlah komoditas demi kualitas model.

OPSI D — Imputasi dari pasar tetangga
  Isi harga pasar kosong dengan rata-rata pasar lain di kecamatan
  yang sama. Perlu asumsi harga antar pasar berdekatan mirip.

OPSI E — Flag kualitas data per titik
  Tandai tiap titik: berapa pasar melapor, confidence-nya. Model bisa
  membobot titik dengan coverage tinggi.

REKOMENDASI (default):
  Kombinasi A + C + E:
    - tetap agregasi pasar-yang-melapor, tampilkan jumlah pelapor (A)
    - untuk model, utamakan komoditas coverage tinggi (C)
    - simpan flag kualitas per titik (E)
  Opsi B & D sebagai EKSPERIMEN, tergantung jawaban divisi analisis
  soal definisi kekosongan.
